# Igris OS

Igris OS is a **Linux-based, AI-native operating system environment**. The Linux kernel is the foundation; the project builds a progressively integrated AI system layer on top of it, connected through structured tools and APIs and governed by a least-privilege permission model.

> **Status: Milestone 7 (sandboxed provider isolation) implemented.**
> The `igrisd` daemon, `igrisctl` client, default-deny permission engine, structured Unix-socket IPC with append-only audit logging, core tool families, and sandboxed provider isolation (namespaces, cgroups, seccomp) are functional.

## Architecture Overview

```
User
  ↓
Igris AI Agent                (Python — agent/)
  ↓
Permission / Security Layer   (Rust — core/igris-permd)
  ↓
Igris Core Services           (Rust — core/igrisd)
  ↓
Linux System Services         (procfs/sysfs, inotify/fanotify, cgroups, seccomp, D-Bus)
  ↓
Linux Kernel
  ↓
Hardware
```

## What Works

### Core Services
- **`igrisd` daemon** and **`igrisctl` client** over a versioned Unix-socket protocol
- **Default-deny permission broker** (`igris-permd`)
- **Append-only JSON Lines audit logging**
- **`system.info`** — live kernel/system data from `/proc` and `/sys`

### Filesystem Tools (confined to `IGRIS_FS_ROOT`)
| Tool | Description |
|------|-------------|
| `fs.list` | List directory entries (bounded, sorted) |
| `fs.stat` | File metadata (type, size, mode, uid/gid, timestamps) |
| `fs.read` | Read file contents (base64-encoded, bounded, truncation flag) |
| `fs.write` | Create or replace regular files (base64 content, confirmation required) |
| `fs.delete` | Remove regular files or symlinks (confirmation required, no directory deletion) |

### Process Observation and Control
| Tool | Description |
|------|-------------|
| `process.list` | Bounded, PID-sorted snapshot of all processes |
| `process.stat` | Metadata for a single process (pid, ppid, name, state, uid, gid, rss_kb) |
| `process.children` | Direct children of a process (not recursive descendants) |
| `proc.signal` | Deliver SIGTERM to a process (confirmation required, self-signaling rejected) |

### Event Observation (Milestone 6)
| Tool | Description |
|------|-------------|
| `events.watch` | Register a filesystem event watch on an absolute path |
| `events.poll` | Drain queued events from a watch (non-blocking, bounded) |
| `events.unwatch` | Remove a watch by `watch_id` (ownership enforced) |

### Provider Sandboxing (Milestone 7)
| Provider | Binary | Capabilities | Isolation |
|----------|--------|--------------|-----------|
| Filesystem | `igris-fs-provider` | `filesystem_read`, `filesystem_write` | Full namespaces, cgroups, seccomp |
| Process | `igris-process-provider` | `process_control` | `/proc` read-only, `proc.signal` limited to SIGTERM |
| System | `igris-system-provider` | (always available) | Minimal: `/proc` and `/sys` reads only |
| Events | `igris-events-provider` | `event_observation` | `inotify` within `IGRIS_FS_ROOT` |

<Note>
Each provider runs in its own sandboxed process with:
- **User namespace**: UID/GID mapping, no root inside sandbox
- **PID namespace**: Isolated process view
- **Network namespace**: No network access
- **IPC namespace**: Isolated IPC resources
- **UTS namespace**: Isolated hostname
- **Mount namespace**: Bind mount + chroot to `IGRIS_FS_ROOT`
- **cgroups v2**: Memory, CPU, PID limits
- **seccomp**: Minimal syscall allowlist (~50 syscalls)
</Note>

<Note>
**Not yet implemented:** Process event observation, Streaming IPC/WebSocket-style event delivery, Event filtering/regex matching, `igrisctl` commands for event operations.
</Note>

## Repository Layout

| Path | Language | Purpose |
|------|----------|---------|
