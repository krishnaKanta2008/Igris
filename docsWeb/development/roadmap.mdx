# Development Roadmap

Igris OS follows an incremental, test-driven roadmap with clearly defined milestones.

## Current Status

> **Status: Milestone 7 Complete** — Sandboxed provider isolation implemented.
> Real provider sandboxing with namespaces, cgroups, and seccomp is functional.

## Completed Milestones

### Milestone 1: Trusted Core IPC
- ✅ Unix domain socket server (`igrisd`)
- ✅ JSON-RPC 2.0 protocol with length-prefixed framing
- ✅ Versioned handshake
- ✅ Append-only JSON Lines audit logging
- ✅ Basic client (`igrisctl`)
- ✅ Permission broker (`igris-permd`) with default-deny

### Milestone 2: Filesystem Read Tools
- ✅ `fs.list` — Bounded directory listing
- ✅ `fs.stat` — File metadata
- ✅ `fs.read` — Base64-encoded file reads with truncation
- ✅ Path canonicalization and confinement to `IGRIS_FS_ROOT`
- ✅ Symlink containment verification

### Milestone 3: Filesystem Write Tools
- ✅ `fs.write` — Base64 content, confirmation required
- ✅ `fs.delete` — File/symlink removal, confirmation required
- ✅ `IGRIS_WRITABLE_PATHS` allow-list
- ✅ Atomic write (temp + rename)
- ✅ Parent directory creation

### Milestone 4: Process Observation
- ✅ `process.list` — PID-sorted snapshot
- ✅ `process.stat` — Single process metadata
- ✅ `process.children` — Direct children only
- ✅ Data sourced from `/proc` only
- ✅ No sensitive data exposure (cmdline, environ, etc.)

### Milestone 5: Process Control
- ✅ `proc.signal` — SIGTERM delivery
- ✅ Confirmation required
- ✅ Self-signaling protection
- ✅ OS permission enforcement
- ✅ `IGRIS_PROCESS_CONTROL` capability gate

### Milestone 6: Event Observation Infrastructure
- ✅ `events.watch` — Register filesystem watch
- ✅ `events.poll` — Non-blocking event drain
- ✅ `events.unwatch` — Remove watch
- ✅ Connection-owned watches with automatic cleanup
- ✅ Bounded queues (16/watch, 256 total)
- ✅ `inotify` backend for real events
- ✅ `IGRIS_EVENTS` capability gate

### Milestone 7: Provider Sandboxing & Isolation
- ✅ Provider architecture: `igrisd` routes to sandboxed provider processes
- ✅ Four sandboxed providers: `fs`, `process`, `system`, `events`
- ✅ User namespace: UID/GID mapping, no root inside sandbox
- ✅ PID namespace: Isolated process view
- ✅ Network namespace: No network access
- ✅ IPC namespace: Isolated IPC resources
- ✅ UTS namespace: Isolated hostname/domainname
- ✅ Mount namespace: Bind mount + chroot to `IGRIS_FS_ROOT`
- ✅ cgroups v2: Memory limit, CPU quota, PID limit
- ✅ seccomp: Minimal syscall allowlist (~50 syscalls)
- ✅ Provider lifecycle management (spawn, monitor, shutdown)
- ✅ cgroups v2 resource limits enforced by kernel
- ✅ seccomp BPF filter with default-deny
- ✅ Provider lifecycle managed by `igrisd` (spawn, monitor, shutdown)
- ✅ Fail-closed: sandbox setup failure aborts provider startup

## Medium Term: Phase 5 — OS-Level Integration

### Systemd Integration
- [ ] Systemd service units for `igrisd` and `igris-permd`
- [ ] Socket activation support
- [ ] Log integration with journald
- [ ] Watchdog/health checks

### D-Bus Integration
- [ ] D-Bus service for system integration
- [ ] Standard interfaces (org.freedesktop.*)
- [ ] Activation via D-Bus

### Security Hardening
- [ ] Seccomp filters for `igrisd` and `igris-permd`
- [ ] Capability bounding (CAP_DAC_OVERRIDE, CAP_KILL only)
- [ ] Landlock LSM for filesystem confinement (kernel 5.13+)
- [ ] SELinux/AppArmor profiles

### Packaging
- [ ] Debian/Ubuntu packages (.deb)
- [ ] Fedora/RHEL packages (.rpm)
- [ ] Arch Linux package (AUR)
- [ ] Homebrew formula (macOS CLI tools only)
- [ ] Docker images (multi-arch)

## Long Term: Phase 6 — Installable Igris OS

### Distribution Formats
- [ ] Bootable ISO image
- [ ] VM images (QCOW2, VMDK, VHDX)
- [ ] Raspberry Pi / ARM SBC images
- [ ] Cloud images (AWS AMI, GCP, Azure)

### Installer
- [ ] Graphical installer (Calamares-based)
- [ ] Headless/automated installer
- [ ] Partitioning and encryption support
- [ ] Post-install configuration

### Base System
- [ ] Minimal Linux kernel config
- [ ] Initramfs with Igris components
- [ ] Immutable root filesystem (optional)
- [ ] A/B partition updates

### Hardware Support
- [ ] x86_64 (primary)
- [ ] aarch64 (Raspberry Pi, ARM servers)
- [ ] RISC-V (future)
- [ ] GPU acceleration for AI workloads
