## Common Patterns

### Request Format

All tools use JSON-RPC 2.0 over the Unix socket:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tool.name",
  "params": { ... }
}
```

### Response Format

**Success:**
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": { ... }
}
```

**Error:**
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32603,
    "message": "Error description",
    "data": { "reason": "specific_reason" }
  }
}
```

### Capability Requirements

Each tool family requires specific capabilities enabled at daemon startup:

| Family | Capability | Environment Variable |
|--------|------------|---------------------|
| System | (none) | — |
| Filesystem Read | `filesystem_read` | (default) |
| Filesystem Write | `filesystem_write` | `IGRIS_WRITABLE_PATHS` |
| Process Observation | (none) | — |
| Process Control | `process_control` | `IGRIS_PROCESS_CONTROL` |
| Event Observation | `event_observation` | `IGRIS_EVENTS` |

## Path Conventions

- All paths **must be absolute**
- Filesystem paths **must be within `IGRIS_FS_ROOT`**
- Paths are **canonicalized** (symlinks resolved, `..` removed)
- Symlink targets **must also remain within root**

## Base64 Encoding

File contents are always **base64-encoded** in both requests and responses:

```bash
# Encode
echo "Hello" | base64
# SGVsbG8K

# Decode
echo "SGVsbG8K" | base64 -d
# Hello
```

## Confirmation Flag

Destructive operations require `"confirm": true`:

| Tool | Confirmation Required |
|------|----------------------|
| `fs.write` | ✅ Yes |
| `fs.delete` | ✅ Yes |
| `proc.signal` | ✅ Yes |
| All others | ❌ No |

## Error Codes Reference

| Code | Constant | Description |
|------|----------|-------------|
| `-32700` | `PARSE_ERROR` | Invalid JSON |
| `-32600` | `INVALID_REQUEST` | Not a valid JSON-RPC request |
| `-32601` | `METHOD_NOT_FOUND` | Unknown tool method |
| `-32602` | `INVALID_PARAMS` | Invalid/missing parameters |
| `-32603` | `INTERNAL_ERROR` | Internal server error |
| `-32000` | `PERMISSION_DENIED` | Policy denied request |
| `-32001` | `CAPABILITY_NOT_ENABLED` | Required capability not active |
| `-32002` | `PATH_NOT_ALLOWED` | Path outside allowed boundaries |
| `-32003` | `CONFIRMATION_REQUIRED` | `confirm: true` missing |
| `-32004` | `RESOURCE_EXHAUSTED` | Limit reached (watches, queue, etc.) |
| `-32005` | `NOT_FOUND` | Resource not found (watch, process) |

## Using with igrisctl

Most tools have `igrisctl` subcommands:

```bash
# System
./target/debug/igrisctl system.info [--json]

# Filesystem
./target/debug/igrisctl fs.list --path <path> [--max-entries N]
./target/debug/igrisctl fs.stat --path <path>
./target/debug/igrisctl fs.read --path <path> [--max-bytes N]
./target/debug/igrisctl fs.write --path <path> --content <base64> --confirm
./target/debug/igrisctl fs.delete --path <path> --confirm

# Process
./target/debug/igrisctl process.list [--max N]
./target/debug/igrisctl process.stat --pid N
./target/debug/igrisctl process.children --pid N
./target/debug/igrisctl proc.signal --pid N --confirm

# Events (not yet in igrisctl)
# Use raw JSON via socket
```
